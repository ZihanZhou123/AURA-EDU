01 / Evaluation Purpose

Why Evaluate the Prototype?

Evaluation Objective

The objective is to assess whether AURA EDU operates according to specified functional and research-data requirements.

评估目标是检查系统是否符合预定功能与 研究数据管理要求，为后续专家评审和 真实学习者研究建立评价基础。

Functional verification, usability evaluation and educational effectiveness are distinct forms of evidence.

01 — Verify Functionality and data integrity
02 — Review Instructional quality and usability
03 — Investigate Future empirical learning outcomes
02 / Evaluation Framework

Six Evaluation Dimensions

1. Functional Correctness

Navigation, grammar module interactions, learner switching and dashboard operation.

功能正确性：页面导航、模块交互和功能操作。

2. Data Integrity

Record preservation, storage readability and backup inspection.

数据完整性：记录保存、读取与备份检查。

3. Identity Consistency

Learner-session association, identity binding and legacy classification.

身份一致性：学习者关联与历史记录分类。

4. Explainability

Trace adaptive recommendations to evidence and decision rules.

可解释性：说明学习路径推荐依据。

5. Usability

Task clarity, accessibility, navigation and learner experience.

可用性：操作清晰度与学习体验。

Further evaluation

6. Instructional Quality

Curriculum alignment, feedback relevance, graduated hints and independent practice.

教学质量：课程匹配、提示、反馈与独立练习。

Expert review planned

06 / Future Evaluation Protocol

Standardised Test Documentation

Future evaluation should document the following information before interpretation.

FieldPurpose
Test ID Unique evaluation identifier
Version / Environment Browser, device and test conditions
Test Objective What the test aims to verify
Procedure Reproducible test steps
Expected Result Predefined acceptance criterion
Observed Result What actually occurred
Evidence Reference Screenshot, log or supporting record
Evaluation Decision PASS, FAIL, REVIEW or NOT TESTED

Define acceptance criteria before testing, record failures and successes, and distinguish developer tests from independent evaluations.
